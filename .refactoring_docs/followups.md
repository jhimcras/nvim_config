# coderunner·rendermark 후속 작업

기준일: 2026-10-30. `.issues/open/`의 Mermaid 지원, 표 이미지 중복 전송, PlantUML 파일 형식 감지, 이미지 붙여넣기 이슈를 통합했다. 아래 항목은 기능 수정 없이 문서와 현재 코드를 대조한 결과다. 표 중복 전송은 통합 검증에서 추가 확인했고, 나머지 신규 기능은 이번 연동 범위에 포함하지 않았다.

## Mermaid 렌더러 설정·실도구 검증

- 상태: 범용 렌더·캐시·그리기 경로는 구현됐다. 현재 `init.lua`에는 PlantUML만 등록되어 있어 Mermaid는 기본 설정에서 렌더되지 않는다. 이전 이슈의 “PlantUML만 지원” 설명은 설정 누락과 기능 미구현을 구분해야 한다.
- 근거: [coderunner 매뉴얼](../docs/coderunner.md)에 `mmdc` 렌더러 설정 예제가 있다. [glue](../lua/nvim_config/markdown.lua)의 `deco_langs()`는 등록된 렌더러의 `match` 언어를 합친다.
- 다음 작업: 실제 `mmdc` 설치·실행 환경을 확인하고 예제대로 렌더러를 등록해 PNG 생성부터 확인한다. rendermark가 SVG 크기를 읽지 못하므로 인라인 표시 검증은 PNG로 한다. Mermaid 전용 캐시나 그리기 모듈을 새로 만들 필요는 없다.
- 완료 기준: Mermaid 펜스가 coderunner 캐시 이미지로 생성되고 neopp에서 인라인 이미지, 터미널 스텁에서 박스로 표시된다. 저장 후 변경 반영과 렌더 실패 표시도 확인한다.

## 표 이미지 중복 전송 재현·원인 확인

- 상태: 미해결 관찰 기록. S3 작업 중 표 셀 이미지의 `vim.ui.img.set`이 `send_images`마다 한두 번 더 호출됐다. 실패 여부와 무관하며 정확한 비용은 미측정이다.
- 2026-10-30 Linux 실제 init+TUI stub 재검증에서는 표 2셀의 배치 안정화 후 같은 배치로 10회 동기화했을 때 `set=0`이었다. 이번 조건에서는 재현되지 않았고 제품 코드를 수정하지 않았다. 과거 관찰의 원인을 해결했다고 표시하지 않는다.
- 근거: [backend](../lua/nvim_config/rendermark/image/backend.lua)의 `apply_payload()`는 이전 항목과 `vim.deep_equal` 비교 후 전송한다. 표 레이아웃이 정착하면서 좌표나 표시 크기가 바뀌는지는 아직 추정이다. 일반 이미지의 무변경 재전송 방지 벤치 통과만으로 표 셀 경로까지 검증됐다고 볼 수 없다.
- 다음 작업: [표 이미지 스펙](../tests/spec/rendermark/table_image_spec.lua)의 가짜 `vim.ui.img`로 표 이미지만 있는 문서를 구성한다. 초기 배치 후 `send_images` 반복 호출 수를 세고, 전송된 항목의 좌표·크기 차이를 기록해 재현을 고정한 다음 원인을 수정한다.
- 완료 기준: 정착 후 같은 배치로 반복 동기화하면 `set` 호출이 0이다. 표 편집·창 크기 변경으로 실제 배치가 바뀌면 필요한 이미지는 갱신되며 기존 이미지·실패 처리 스펙도 통과한다.

## PlantUML 파일 형식 자동 감지

- 상태: 감지 설정 보완 대기. 기존 관찰 환경은 Neovim 0.12.4다. `.puml`·`.plantuml` 등을 열어도 파일 형식이 지정되지 않아 수동 `:set ft=plantuml` 전에는 문법 하이라이트가 켜지지 않았다.
- 근거: [플러그인 설정](../lua/nvim_config/plugins.lua)은 `aklt/plantuml-syntax`를 `FileType plantuml`에서 로드한다. 감지 규칙도 해당 플러그인에 있어 파일 형식 감지가 로드 조건을 충족하지 못한다. previewer 제거 이전부터 있던 문제다.
- 다음 작업: 지원할 확장자 목록(`puml`, `plantuml`, `pu`, `wsd`, 필요 시 `iuml`)을 정하고 `vim.filetype.add`로 직접 등록하는 최소 변경을 검토한다. 플러그인 로드 조건 변경도 대안이다.
- 완료 기준: 새 Neovim에서 해당 확장자 파일을 열면 `filetype=plantuml`이 되고 하이라이트·들여쓰기가 동작한다. Markdown 펜스 언어의 렌더러 `match`와 파일 확장자 감지는 별도 계약이다.

## 클립보드 이미지 붙여넣기

- 상태: 미구현 기능 요청. 현재 설정의 `unnamedplus`는 텍스트 클립보드 연동이며 이미지 저장·링크 삽입 기능은 없다.
- 다음 작업: 저장 폴더·파일명·충돌 처리와 Markdown 링크 형식을 먼저 정하고 Windows/Linux의 이미지 클립보드 접근 방법을 확인한다. [coderunner 내보내기](coderunner.md)와 기존 이미지 경로 규칙을 참고하되 다이어그램 렌더링과 별개 기능으로 다룬다.
- 완료 기준: 지원 플랫폼에서 클립보드 이미지를 지정 위치에 저장하고 현재 Markdown 문서에 올바른 링크를 삽입한다. 파일 충돌이나 이미지 없음의 처리 방식도 검증한다.
